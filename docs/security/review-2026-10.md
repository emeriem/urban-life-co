# Security review — October 2026

## Controls included in the current security reconciliation

- Contact submissions validate required fields and email format, cap field lengths, accept only known enquiry types, include a honeypot, and limit repeated submissions.
- Media listing is restricted to administrators and returns only the fields needed by the CMS.
- Image uploads allow only JPEG, PNG, WebP, and GIF.
- Update handlers prevent client-supplied identity and creation timestamps from overwriting stored record metadata.
- The service worker excludes API and cross-origin requests from its cache and bumps the cache version to purge older entries.
- Google Photos import uses runtime-compatible byte conversion and does not rely on Node's `Buffer` global.

## Administrator allowlist caveat

The deployed AppDeploy validator currently requires a literal fallback administrator allowlist in `backend/index.ts`. The encrypted `ADMIN_EMAILS` AppDeploy secret takes precedence when configured, but the fallback means the admin address is present in public source control. This is a temporary platform-compatibility trade-off, not the preferred end state. Remove the source fallback once AppDeploy supports secret-only allowlists, and ensure the secret is configured in every target environment.

## Deployment prerequisite

Confirm that the encrypted `ADMIN_EMAILS` secret is configured in the target AppDeploy environment with the authorised administrator address or addresses, comma-separated. Validate authenticated administrator access after deployment.
